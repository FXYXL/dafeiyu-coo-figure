## 两个版本怎么选

功能完全一样，区别只在清晰度和包体：

| | 标准版 | 高清版 HD |
|---|---|---|
| 当前版本 | **1.14.49** | **1.6.18** |
| 渲染画布 | 1024 × 1024 | 2048 × 2048 |
| 贴图 | 长边 ≤ 2048 | 原始 4096×8192 / 8192²，运行时按 4096 封顶 |
| 压缩包 | 约 28 MB | 约 60 MB |
| 适合 | 一般屏幕、长期挂着 | 高分屏、大尺寸、要截图/录屏 |

两个包的 `id` 不同（`deepseek-shenggong` / `deepseek-shenggong-hd`），**可以同时装**，在装扮页分别选。
HD 的贴图更大、显存占用更高，机器吃力就用标准版。

## 安装（两步 + 重启）

分两步：**放形象** + **打补丁**。只放形象不跑补丁的话，摸头、戳一戳、悬停、拖拽、小剧场
这些实时反应都不会出现——那些逻辑在桌宠引擎里，不在形象包里。

> 打补丁需要 **Node.js 18 或更新**（[下载](https://nodejs.org/)）。只是用形象不跑补丁的话不需要。

### 第 1 步：放形象

1. 下载本仓库（或 Release 里的 zip 并解压）
2. 把**含 `figure.json` 的那一层目录**整个放进：

```
<Coopanion 数据目录>/home/companion/data/figures/
```

Windows 上通常是：

```
C:\Users\<你>\AppData\Roaming\Coopanion\data\home\companion\data\figures\
```

目录名随意（比如 `dafeiyu`），但里面必须有 `figure.json`，Coo 靠它识别形象。

### 第 2 步：打补丁（必须）

听歌集成与微抖修正、补丁测试和回退说明见 [tools/music/README.md](tools/music/README.md)。


桌宠引擎（`cortico-world-desktop-pet`）是随 Coo 安装的，补丁改的是它里面的文件——
一共 **83 个补丁，分布在 10 个文件**（`body.js` 45 个，另有 `pet-app.js` / `script.ts` /
`server.ts` / `world` 等）。

```bash
cd <本包目录>
node tools/patch-pet-kit.mjs --dir="C:/你的/Coo安装目录"
```

- `--dir` 传 **Coo 根目录** 或 **引擎目录** 都行，脚本会自己找
- 不传 `--dir` 时会自动探测常见安装位置（Program Files、`%LOCALAPPDATA%\Programs`、D/E 盘的 `Coopanion`）
- **不知道 Coo 装在哪**：任务管理器 → 详细信息 → 右键 `Coopanion.exe` → 「打开文件位置」
- 路径里有空格要加引号；也可以直接拖文件夹到命令行里取路径

常用参数：

| 命令 | 作用 |
|---|---|
| `node tools/patch-pet-kit.mjs --dir="..."` | 打补丁（已打的会跳过） |
| `... --check` | 只检查，不写文件 —— 想知道自己打没打全就跑这个 |
| `... --revert` | 按补丁事务快照还原到本次应用前的状态 |

**验证是否打全**：`--check` 应以「全部补丁和资源内容检查通过」结束；缺失补丁或资源内容不符会返回非零退出码。

> **Coo 每次更新都会覆盖这些文件**，更新完重跑一次补丁。
> 应用前会预检全部目标，并用 `.petkit-transaction.json` 保存首次应用前的快照。`--revert` 恢复原文件和原有资源，不误删此前已有的音乐资源；旧 `.bak-petkit` 仅作无事务快照时的兼容回退。

> **如果 Coo 更新后补丁开始报 `✗ 找不到锚点`**：说明引擎源码结构变了，补丁需要跟着适配。
> 到 [Issues](https://github.com/FXYXL/dafeiyu-coo-figure/issues) 提一下，附上 `--check` 的完整输出
> 和你的 Coo 版本号（设置 → 关于）即可。形象包本身仍然能用，只是对应的那几个新交互会失效。

### 第 3 步：完全退出再启动

不是关窗口——**从托盘退出 Coo**，再启动。然后在形象面板里选「大肥鱼」。

## 她会怎么回应你

| 操作 | 反应 |
|---|---|
| **右键按住头 / 脸** | 摸头：转头看你、眯眼笑、脸红，按得越久表情越深；松手后按摸的时长分四档（见下表） |
| **左键拖拽** | 拎起来走：身体朝运动方向倾、头甩在后面，停下时头还会晃两下；快速甩才有一点形变，慢慢移动不会像橡皮 |
| **左键点不同部位** | 戳一戳：头、脸、胸口、裙摆、腿、尾巴各有不同反应，而且她会往**反方向**躲 |
| **鼠标停在身上不动 10 秒** | 一条轻微反应（30 秒冷却；戳/拖之前不会误触发） |
| **不管她** | 待机：模型自带的 `IDLE` 动作循环（泪花、闪光等微特效）；闲时按权重自己抽表情和小动作；偶尔演一段 19 段彩蛋小剧场 |
| **刚出现 / 摔到地上** | 出场会抬手打招呼；从高处落地会有落地反应 |

### 摸头四档

| 摸的时长 | 松手后 |
|---|---|
| < 3 秒 | 轻摸：有点失落，低头 |
| 3 ~ 8 秒 | 不舍得你走 |
| 8 ~ 20 秒 | 腻歪，往前凑 |
| 20 秒以上 | 融化 6 秒，带爱心眼 |

## 词表与语法

当前共 **136 个词**：23 个表情 + 113 个动作。完整清单（含说明、时长、是否保持）见
**[WORDS.md](WORDS.md)**，那份文件由 `figure.json` 自动生成，永远和词表一致。

### 怎么写

- **`<词>`**：跟着打字走的小动作，比如 `<歪头>`、`<点头>`
- **`【词】`**：另起一个气泡的整段表演，比如 `【委屈】`
- 中文名和英文 id 都认：`<tilt>` 等价于 `<歪头>`
- 一次 1~3 个词最自然；不同部位的词会同时生效（`<歪头>` + `<鼓腮>` + `<脸红>`）

### 修饰与方向

| 语法 | 作用 | 例子 |
|---|---|---|
| 微 / 大 | 幅度减半 / 约 1.5 倍 | `<微鞠躬>`、`<大跳一下>` |
| 快 / 慢 | 节奏加快 / 放缓 | `<快点头>` |
| ×2 / ×3 | 一次性小动作重复 | `<点头×3>` |
| `:右` | 方向词镜像（默认朝左） | `<瞟一眼:右>` |
| 恢复 | 清空所有表情 | `<恢复>` |

### 叠加规则

- **附加层**（脸红、冷汗、流泪、兔牙）可以互相叠
- **整脸表情**（黑脸、圈圈眼、爱心眼、无语、狐疑）一次只有一张脸，新的顶掉旧的
- 标了「保持到下一个动作」的词会一直挂着；大多数会自己放松淡掉，不用特意收

## 听歌摆动

Windows 下播放音乐后，她会估计节奏并轻轻摇摆，跳一段时间后轮换三种音乐表情。动作按句衔接，BPM 改变在下一句生效，音量不会直接拉扯动作幅度。

在装扮页的「听歌反应」中选择来源：默认只认音乐软件，也可允许浏览器、接受所有系统声音，或关闭。网页播放器没有反应时，先选「音乐软件 + 浏览器」。判定需要持续声音和数个有效拍点，不会一出声就起舞。

摸头、拖拽、说话、走路和已有表演会按原有优先级让位；听歌期间抑制随机动作，避免小剧场突然插入。停止播放后有短暂保持，关闭听歌开关则立即撤掉舞步和音乐脸。

**升级时需要同时更新形象包并重新运行引擎补丁，然后从托盘完全退出并启动 Coo。** 本版修复了待机手指和摇摆头部的细小抖动，以及首次集成中可能出现的「custom is not defined」回退错误。

系统音频通过 Windows WASAPI 在本机提取音量、频谱和应用电平，不保存或上传音频。其他系统目前不提供自动听歌。

## 装扮开关

服装不是三套写死的套餐，而是七根独立的轴，在 Coo 装扮页里逐项选、任意搭配
（装扮页一共 8 根轴，最后那根是「听歌反应」开关）：

| 轴 | 选项 | 写的参数 |
|---|---|---|
| 大小 | 默认 / 稍小 / Q 版 | `Clothes2`（0 / 0.4 / 1）+ 写死的取景 `fit` |
| 服装 | 长裙装 / 短裙装 | `Clothes1`（0 / 1） |
| 鞋 | 穿鞋 / 脱鞋 | `Clothes4`（0 / 1） |
| 头顶 | 不戴 / 扣钢盆 | `key10`（0 / 1） |
| 胸口 | 默认 / 胸口上拉 | `Clothes3`（0 / 1） |
| 尾巴 | 有 / 关 | `Clothes5`（1 / 0） |
| 眼镜 | 不戴 / 黑框 / 单片 | `key11` / `key12`（互斥，避免一只眼睛叠两副） |
| 听歌反应 | 音乐软件 / 音乐软件 + 浏览器 / 所有系统声音 / 关闭 | 音频来源筛选，不写模型参数 |

**两条硬规矩**（踩过坑）：

- 每个选项**只写自己这根轴**的参数。`resolveScheme` 是多轴 `Object.assign` 合并，写了别人的参数就会把别人的选择覆盖掉。
- 每根轴**必须显式写关闭态**（比如"不戴"也要写 `key10: 0`），否则从"打开"切回"默认"时旧值会留在参数里，模型不会自己复位。

这套参数对应关系是从 Live2D 一键导入插件生成的包（`native-library.json`）里读出来的，比模型自带的 exp3 更省事 —— 直接写参数，不用挂表情。

## 技术说明（改包之前读）

### 表演系统：一张表管所有表演

表情槽、动作轨道、外力叠加（rua）不再是三个抽屉，而是统一进 `layers[]`。每条东西自带四件事：
写哪些参数、用常量还是关键帧、演多久、怎么混。合成规则三条：

- **常量覆盖**：同一参数只留最新
- **关键帧 / 波形相加**：点头叠在歪头上会转得更远
- **手型与贴图取最新**：不会两只手同时抬

整段表演（情绪、摸后四档、戳一戳）也是一个「组」：组管权重、手势、延迟，组里每个参数是表里的一条。
所以所有参数只有一个出口；两条表演交接是淡入淡出，不是硬切。

### 参数写入顺序

每帧的写入顺序是有讲究的，动错一层就会出现「表情残留」「眼镜不显示」「换大小后悬空」这类问题：

```
loadParameters        载入上一帧基准
applyFrame            角色姿势（role 层：眼、嘴、呼吸、情绪）
applyCleanParams      清理值
applySchemeParams     服装 / 大小（状态量，会写 key9~12）
saveParameters        把上面三层存成下一帧基准
stepMotion            模型动作
stepExpression        表情（临时覆盖，优先级最高）
applyPartOpacity
physics / pose
update
```

- `applySchemeParams` 必须排在 `stepExpression` **之前**：否则服装方案把 `key9~12` 按回 0，眼镜、钢盆永远出不来。
- `saveParameters` 必须在 `stepExpression` **之前**：否则表情参数被存成基准，表情停了也回不去（表现为圈圈眼/白眼常驻）。
- 换 scheme 时要 `extent = null` 重新取景，否则会沿用上一套缩放（Q 版切回默认变巨大半身像）。

### 物理：头发 / 尾巴 / 裙摆 / 胸

模型自带 `physics3.json`（131 条链）本来就在跑，但桌宠里没有面捕，`PositionX/Y/Z`、`AngleX/Y/Z`
都是常量，物理算出来一直是 0。现在分四层：

1. **动作时的大幅甩动**：`AngleX/Y/Z` 同时写绘制用的 `AngleX` 和前发物理的 `ParamAngleX`，一转头头发、尾巴、帽带跟着甩。
2. **静止时的呼吸级微摆**（`idlePhysics`）：给物理的**源头输入**叠很慢的正弦（`ParamBreath`、`PositionX/Y/Z`），让物理持续有活干。**只写源头参数**——`ParamBodyAngleX/Z`、`HipAngleX/Z` 是物理的输出，写进去会被下次 `evaluate()` 覆盖。
3. **指针跟随躯干**（`bodyFollow`）：光标左右 → 肩膀、躯干、裙子一起倾。**必须写在 `physics.evaluate()` 之后**，因为这些是物理输出参数。
4. **裙摆 / 胸的幅度补强**（`physicsWaves`）：这两组物理链很"硬"，输入拉满也只输出 3~4%，所以在物理之后再叠同频正弦，把幅度提到 8~14%。`spread` 是同组相位差，让摆动从根部往梢部传。

> 参考的另一种实现（pixijs-live2d）把指针直接映射到 `ParamBodyAngle*`，因为那套渲染里这些参数不算物理输出。
> 同一份模型放到 Cubism 原生物理下，就只能绕到物理之后写。

### 动作实现

- 时间轴由 `clockT` 自己算（`act.dur` 秒），**不跟 kit 的 `frame.gesture.k` 走**：实测 `k` 会卡在中途（甩草永远停在 0.314），按 `k` 换算秒数的话动作只播开头一小段就定格。过渡与节奏统一走 `actWeight(t, dur)`。
- 参数动作写在 `applyParamActs()`，配置全在 `profile.paramActs`。
- `ParamBodyAngleZ`、`HipAngleZ` 这类物理输出参数要驱动的话，声明在 `postWaves`，由 `applyActPostWaves()` 在物理之后写（`wiggle` 就是这么做的）。
- **手臂是"切换"不是"骨骼"**：三只备用手由 `Movement1/2/3` 切换，位置靠 `Param41/42` 这类网格变形参数控制。切回来时要把另外两个显式归零，否则会叠在一起。

### 闲时池：她自己会做什么

`IDLE.motion3` 只驱动泪花/冒汗/闪光这类特效参数，不含手臂。VTS 里看到"待机自己换手"
其实是它的 Auto Idle。这里用 `profile.idleRepertoire` 模拟：**表情（挂着的情绪）和小动作放同一个池子**，
由 kit 的 `decide()` 按权重抽——高频的歪头、瞟一眼、点头权重 3，手部姿势和小剧场 4，彩蛋级 1~2。

池子里现在有 34 个条目（14 条表情 + 20 条动作），抽中后走正常词入口，音效、爱心、压扁都有。
小剧场权重压到 4：它一段要占 15~30 秒，按「占用时间」算比单动作重得多。
想更活跃就调高权重；不想让某个动作出现就从池子里删掉。

### 重新打包后如何恢复

插件的 `convert.mjs` 每次会重新生成 `profile.js` 和 `figure.json`，上面的定制会被清空。

```bash
python port-custom.py <本仓库目录> <新打好的包目录>
```

它会覆盖 `profile.js`、`models/index.js`、`motions/`、`expressions/`、`thumb/`，并合并 `figure.json` 的
`axes` / `vocab` / `about` / `version`，其余字段保留新包自己的。渲染层（`backends/live2d.js`）的改动已同步进插件模板，重新打包不会丢。
词表有增删的话，再跑一次 `node tools/gen-words-doc.mjs` 更新 `WORDS.md`。

## 已知限制

- **手臂没有骨骼**：三只备用手靠 `Movement1/2/3` 切换，位置由网格变形参数控制。能举手、放下、来回挥，做不了招手、连续挥臂这种多关节动作。
- **拖拽时脚会反向飘一点**（形象高度的约 9%）：整图旋转的支点在脖子，脚离支点远，这是几何必然。想彻底消除需要改走骨骼参数（`PositionX → ParamBodyAngleX`），目前的效果更像「拎着一只活物」，暂时保留。
- **「稍小」「Q 版」的取景是写死的数值**（`zoom` / `offset`），换模型不通用。
- **HD 的贴图很大**：8192² 的贴图按 4096 上传，仍比标准版吃显存；机器吃力就用标准版。
- `models/deepseek/moc3.js`（21 MB，moc3 的 base64 副本）是旧沙箱不能 fetch 二进制时的兜底，多数环境用不到；想瘦身可以删，但失败时没有回退。

### 动作与曲线的参考来源

| 动作表 | 点头/摇头/鞠躬/歪头/抚胸/竖手指/狗尾草/思考等姿势的目标值与过渡 |
| 交互阈值 | 悬停 10 秒 / 冷却 30 秒、rua 分档 3/8/20 秒、戳一戳的六条反应与左右镜像 |
| 表演数据 | 小剧场的动作编排、口型时长与标点停顿 |

没有那份实现作为对照，这个包不可能在参数不全、文档缺失的情况下把这些细节调到能用。**它的原创设计与代码版权归原作者**；本包只使用了其中可观察的行为与数值，并按本项目的数据格式重写了一遍（Live2D 参数名、Coo 的 figure 接口、JS 而非 C#）。如果原作者认为某些数值不宜被沿用，请联系我调整。
